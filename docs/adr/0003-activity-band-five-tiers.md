# 活跃分带：五档划分与「活动时间」口径

Status: accepted

活跃分带由四档改为五档：活跃（3天内）、近期（3-7天）、渐冷（7-30天）、沉睡（30-90天）、归档（90天+），分带依据从「最后提交时间」改为「最后活动时间」——取最后提交、AI 会话痕迹、未提交改动文件修改时间三者的最大值。

驱动力是 vibecoding 场景下的系统性误判：提交低频、AI 会话高频，只认提交时间会把「昨晚刚和 AI 改了一轮但还没提交」的项目错划进冷却档，这正是本工具要防的决策漂移场景。拆出 90 天+ 的归档档，是因为「一个月没碰」（搁置可捡回）和「一年没碰」（事实归档）对回忆工具是两种东西，混在一档会污染主面板。

考虑过维持只认提交时间（「没提交等于没进展」），被否：它会埋掉核心场景。代码内英文 key 保持 hot/active/cooling/stale 不动、新增 archive，仅中文标签更名，改动面最小。
