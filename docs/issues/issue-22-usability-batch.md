# 【审查·AI·可用性·低】可用性小项合集：黑名单无复位口 / 错误原文上屏 / 手动任务标自动 / 筛选落地不校验上下文

- 级别：低 ｜ 轴：Standards + Spec ｜ 维度：可用性

一组低危可用性项，建议一次 PR 打包，逐条独立可验。

## 清单

1. **会话黑名单无复位口**——`src/main/ipc.js:490-491, 560`：`sessionBadEngines` 任何失败（含偶发超时）即拉黑整会话；用户在终端修好登录/配额后，只要还有别的引擎活着，该引擎永不再试。→ settings:set 变更 AI 配置或手动「重新生成」时清空该集合。
2. **引擎英文错误原文上屏**——`src/main/ai.js:24` → `src/renderer/app.js:798`：原始错误行（截 120 字符）直接拼进「AI 生成失败：…」，普通用户读不动。→ 主进程侧映射为中文类别（配额/鉴权/超时/未安装），原文仅进 console。
3. **手动任务被标成自动**——`src/renderer/app.js:915-921`：cachedOnly 回 pending 后并入在飞任务时补 `j.auto = true`；若原触发是手动（页面重载/死任务清理后），失败将走 app.js:901 的静默分支，手动点击者得不到任何错误反馈。→ 并入已有任务时不置 auto，或 auto 仅标记「本进程内无人工触发过」。
4. **AI 筛选落地不校验上下文**——`src/renderer/app.js:982-997`：在飞期间用户已 Esc/切走/改了查询词，结果落地仍强制执行 switchView + 改 band。→ 落地前校验 `state.query` 与发起时一致且搜索上下文仍活跃。

## 验收

修好引擎后手动「重新生成」即恢复首选；引擎故障时错误提示为中文类别；手动触发失败一定有可见反馈；解析在飞期间 Esc 后结果不再强行落地。
