# 【审查·集成·中】GitHub 连接导入/断开后无即时拉取触发，「落地即推补丁展出」缺口

- 级别：中 ｜ 轴：Spec ｜ 规格出处：CONTEXT.md:85「连接导入即持久化登录名，数据拉取落地后立即推补丁展出，无需重启」（issue #44）
- 位置：`src/main/ipc.js:723-755`；`src/renderer/app.js:2640-2647`、`:2953-2991`、`:1293`

## 问题

`github:importGh` / `devicePoll` / `disconnect` 只写配置，渲染层成功回调也不调 `refresh`。「落地即推补丁」机制本身在（ipc.js:393-404），但首次拉取要等下一个刷新触发点（手动刷新/唤出 tick/后台定时，默认最长 20 分钟）。期间打开本人仓库详情页会误显「非本人项目，不拉取 GitHub 数据」（app.js:1293，旧板 `githubOwned=false` 所致），开放 PR 警示同步延迟。

## 方案

连接/导入/断开成功后立即触发一次 GitHub 拉取并走既有补丁推送链路：

- 主进程侧：三个 handler 写配置成功后调用既有拉取+拼板函数（复用 ipc.js:393-404 的落地即推路径），无需渲染层配合；或
- 渲染层侧（最小改动）：三处成功回调追加 `refresh(true)`。

推荐主进程侧方案，断开连接时同样立即重推（清掉 GitHub 区块）。

## 验收

设置页完成 Device Flow 授权后 5 秒内，本人仓库详情页出现 GitHub 区块、开放 PR 警示就位；断开后区块即时消失。
